## 打开

本机安装目录使用原来的 `pcg_grid_preview` 包名，插件显示名改为 **PCG DCC Module Authoring**。保存当前工作后重启 Blender，打开 `PCG_DCC_Demo.blend`。鼠标放在三维视图，按 N → **PCG DCC**。

也可以在 Scripting 文本编辑器打开 `run_preview.py`，点击 Run Script，重新加载当前仓库代码。安装包为 `pcg_grid_preview.zip`，包含代码和 254 状态的标准灰模数据。

## 创建模块

1. 点击 **创建模块**。填写层级 ID，例如 `building.roof.end`；“预选已有 ID”只负责填入已有路径，仍然创建独立模型。
2. 设置 V1–V8 启用状态。V1–V4 顶层，V5–V8 底层。左侧字符对应 V1，按 bit0 起排列。
3. 保持“复用相同 Bool 的已有或父模块灰模”时，优先复制匹配状态的最近父模块；取消后使用项目内置标准表面灰模。
4. 相同 ID 允许多个模型。同 ID 使用不同 Bool 会提示冲突但仍可创建；每个模型有独立内部唯一键。移动、改名和保存重开不改变唯一键。
5. 模型自动放入 `PCG Modules / building / roof / end` 等集合。ID 分组可折叠。

全空 0 和全实 255 只创建空网格与参考笼，不产生表面。标准灰模来自项目原始 Marching Cubes 基础库，不是最终建筑美术。

## 注册已有模型

1. 选中源网格，点击 **注册已有模型**。
2. 三维视图出现带 V1–V8 角标的参考框。移动、旋转、缩放框，或将模型调整到框内。
3. 点击 **确认注册**，填写 ID 和 Bool。
4. 工具把模型的求值几何换算为参考框的规范空间，烘焙当前修改器；参考框绑定到模型。整个操作支持 Ctrl+Z。

模型的规范本地范围是 `[-0.5,0.5]³`；参考框的世界摆放不属于资产几何。注册后检查越界、退化面和无效引用。取消注册会移除临时框，不修改模型。

## 约束编辑

选择当前模块后，使用上、下、前、后、左、右标签页添加候选 ID，权重默认 1。父 ID 匹配其自身及全部子 ID，例如 `building.wall` 包含 `building.wall.window`，不匹配 `building.wallpaper`。

特殊候选：`$empty` 空气，`$solid` 实心，`$outside` 真实地图外侧。内置辅助灰模使用 `base.s000` 风格的状态分类，例如 `base.s240`；直接指定 `base` 可匹配全部内置灰模。模型自身 ID 不允许以 `$` 开头。

新增或修改连接时，自动生成几何、Bool、朝向兼容的反向关系。带 `↔` 的条目是自动反向，点击其编辑或删除会转到原始声明。修改连接不会自动放宽其他规则来制造可解结果。

没有显式候选时使用自动几何匹配。混合 Bool 面标橙色“未配置”，全空、全实的面不会被一律高亮。添加候选后该面限定在候选集合；删除到空列表表示无法连接。**恢复自动**解除本面手动限定，并重新生成反向缓存。

权重是相对偏好。界面按本面候选条目显示归一化比例，不代表最终全局频率。当前编辑模型始终固定，不参与随机替换；只有辅助区多个合法候选之间使用权重。

## 三组预览和实时编辑

### 镜像与匹配

模块的“允许镜像”只控制局部 X 轴左右镜像，作者模块默认关闭；既有四个水平旋转默认允许。开启后先左右镜像，再应用允许的水平旋转，模型、八角 Bool 和六面规则一起变换并参与匹配。四个角度和镜像都允许时最多 8 个变体；无上下翻转。JSON 恢复使用 allowMirrorX。

镜像会改变文字、标识或固定左右关系时应关闭。普通墙体、屋顶的不对称本身不构成禁止理由；只要镜像后的外观与功能仍符合设计就可允许。接口或 Bool 不匹配由匹配器排除相应姿态，不能用禁止整个模块镜像替代接口约束。

### 预览操作

1. 点击 **生成 / 刷新预览**。三价、四价、五价各有一组独立网格。
2. 每组只在其中一个核心 Cell 填入当前模块。其余扇区和外扩网格仅作线框参照；只为当前格的六个直接共面邻格匹配辅助模型，禁止辅助模型使用当前精确 ID。默认三层、当前模型在中间层。
3. 每个邻格独立匹配与当前格之间的共享面 Bool、几何接口和双向语义。不检查邻格其他面的约束，不从邻格继续传播，也不要求这些邻格彼此形成全局一致的场景。未填入的格子保持空白；权重只用于直接邻接的合法候选。

   **有效面门槛：先检查旋转／镜像后的当前模块 Bool。某面四角全部未启用时，该方向不查候选、不计算权重、不生成辅助模型，即使保留了显式候选也跳过；之前生成在该方向的辅助模型会清理。四角中至少一个启用，才匹配这一面的直接邻接。四角全启用仍属于有效面。**
4. 辅助区裁切边界保持开放，不默认当作空气或地图边界。核心显式邻接超出范围时提示“范围不足”，可调整所在层或层数。
5. 所有模型始终只固定一个核心 Cell，不再提供铺满核心区的开关。可指定合法的固定朝向。
6. 点击 **3价 / 4价 / 5价** 直接进入对应核心实例的编辑模式，或直接选择核心实例后按 Tab。辅助模型和变形笼禁止选择，核心实例的对象移动、旋转和缩放锁定。
7. 三组核心实例和原模共享源网格，修改顶点、增加边面会同步。各实例使用独立的线性变形笼显示，不把变形烘焙进源网格；不要应用或移除显示变形笼。
8. **换一组**才改变组合种子。几何内部修改后，只要原直接邻接仍合法，就继续使用它。接口变化导致不合法时重新匹配。辅助模型的其他面即使没有候选，也不阻止当前格预览。

无解时保留当前编辑对象、移除无效辅助结果，并标记冲突面；不会回退成另一块模型。三组结果独立，一组失败不影响其他组。**清理**只删除工具生成的预览对象，不删除源模型。

## 注册表检查和重建

点击 **检查注册表**，按 ID 展开条目，悬停模型按钮可查看完整信息；点击条目选择源模型。视图中橙色面为未配置、红色面或点为失效、黄色线框为同 ID Bool 提醒。检查后悬停高亮位置可显示原因，Esc 结束悬停提示。

- 未配置：根据面角点 Bool，需要连接定义但未配置。预览仍可以几何匹配作为建模参考。
- 规则失效：ID 丢失、几何或 Bool/朝向不匹配、非法 ID、权重、越界点或退化面。
- 场景无解：局部候选存在，但当前固定布局无法同时成立。

**按当前 Bool 重建标准灰模**会替换当前网格和修改器，保留 ID、唯一键和规则，并重新校验。支持撤销，不会静默覆盖其他同 ID 模型。重命名 ID 分组会同步其子路径和邻接引用；删除源模型后，失效引用保留供检查。

## 导出 Unity

### 开发阶段：保存 Blender 工程

1. 安装新版插件并启用 **PCG DCC Module Authoring**。已有 Blender 窗口应先保存工作再重启，或运行仓库 `run_preview.py` 重新加载代码。
2. 将工作工程保存在 Unity 项目的 **Assets/DCCSources/** 下，允许子目录。已提供 `Assets/DCCSources/Buildings.blend` 作为独立开发示例；原始 `Assets/Art/BaseModel/PCG.blend` 未修改。
3. 在 Blender 内修改源模型、Bool、ID 或候选，按 Ctrl+S。插件在保存前生成隐藏的 **PCG Unity Transfer** 集合：规范化源网格、53 个基础模型族、稳定 UUID 和紧凑 JSON 规则。无需手动维护 JSON，也不额外导出 FBX。
4. 切回 Unity 等待原生 `.blend` 导入完成。导入器读取自定义属性，按 UUID 绑定源网格，将网格统一到模块坐标，并移除导入层级中的建模布局、预览实例、参考框和变形笼。它不修改 Blender 中的预览。
5. 自动生成同目录 `Buildings.tileset.asset`。开发时将此资产赋给 `UnifiedGridBuildingDemo` 的 Building Tileset 字段；它是模块库，不需要将整个 `.blend` 模型拖入场景。
6. 对源文件重新命名或移动时使用 Unity Project 窗口，且保留在 Assets/DCCSources 内；配套 `.tileset.asset` 自动跟随，保留 GUID。普通重导入和规则更新同样保留已编译资产身份。

此路径要求本机能被 Unity 找到的 Blender。Unity 使用自己的原生模型转换流程，新增导入器不再启动第二次 Blender。只有 Assets/DCCSources 下的 `.blend` 会启用此处理，其他模型保持原有导入流程。

不要编辑隐藏传输集合。每次保存会从真实源模型重新生成；插件未启用时保存不会更新传输快照。源规则无效时，保存仍保留制作工程，但快照标记失败，Unity 报错并保留上一次有效的编译资产。Play Mode 期间暂停规则库编译，回到 Edit Mode 后补做。多场景工程只生成当前活动场景的快照；请将一个模块库放在一个活动场景中维护。

### 正式交付：FBX + JSON

**导出源模块 FBX + JSON**只导出源资产，不包含预览实例、变形笼和注册参考框。自动附带规范基础模块，使运行时可以覆盖 254 个表面状态。

输出 `DCCModules.fbx` 和 `DCCModules.tileset.json`，兼容项目现有 Unity Tileset 导入器。逻辑层级 ID 写在 `logicalId`；JSON 的 `id` 使用稳定内部唯一键，规则展开到具体源模块，避免同名模型冲突。轴转换和单位设置由工具统一完成。

示例导出位于 `Assets/Art/Buildings/DCC/`。在 Unity 中等待编译为 `.tileset.asset`，赋给 `UnifiedGridBuildingDemo` 的 Building Tileset 字段。当前 Unity Demo 仍使用统一预览材质。

这条路径无需接收方安装 Blender。FBX 与 JSON 应作为同一批次一起提交更新。`logicalId` 现在也保留到 Unity 编译变体中；匹配和绑定继续使用稳定唯一 ID。

在 Unity 选中 `.blend` 可使用 **Tools → Marching Cube → Building Tileset → Compile Selected Blend** 手动编译；选中 JSON 对应使用 **Compile Selected JSON**。编译资产 Inspector 的“重新编译”根据源类型自动选择对应路径。

### 2.1.2 同类邻接与独立注册表

局部预览允许同一源模块及相同逻辑 ID 出现在直接邻格中。每个实例仍需通过 Bool、几何接口与双向语义匹配，不继续传播邻格的其他面。

在 N → PCG DCC → 模块注册表，点击“打开完整注册表（独立窗口）”。窗口按点分 ID 层级分组，可折叠、搜索 ID/对象名/唯一键，查看各模块的 UUID、网格、八角状态、基础权重、旋转、镜像和六面候选。候选标明手动/自动反向来源，权重按钮复用原有可撤销编辑流程。规则明细的百分比是本面配置权重占比，不代表经过 Bool 与几何筛选后的最终概率。开启“显示原始规则 JSON”可查看完整源规则，缺省面代表自动几何匹配。检查提示标为“上次检查”，点击“检查全部模块”刷新。关闭独立窗口不删除模块。

2.1.3：修复侧栏规则按钮沿用历史模块 UID、方向和规则索引的问题。添加始终绑定当前模块/当前面，并重置历史索引；编辑按所选规则的实际面定位，避免添加变成覆盖其他模块的规则。

2.1.4：规则目标 UID、方向、索引和候选搜索预选禁止沿用历史操作参数；注册表入口同样显式绑定方向并清除索引。`tests/blender_rule_binding.py` 在临时 Blender 场景中验证衍生模块网格/唯一键/手动规则独立、反复切换模块与方向的按钮绑定，不保存工程。
