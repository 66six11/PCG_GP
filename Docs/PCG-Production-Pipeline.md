# PCG 模块化生产流程规范

版本：提案 v1.0；日期：2026-10-25。

适用范围：本项目 Blender → FBX → Unity 的不规则网格建造流程。本文规定目标生产流程，不代表所有功能已经实现。新增类型名均为建议名称。

## 1. 目标与现状

目标：同一建筑中，外壳可随网格形变，门窗、设备等保持尺寸，栏杆等按段拼接；编辑、撤销、保存与重建结果一致。

| 环节 | 已有能力 | 待实现能力 |
| --- | --- | --- |
| Blender | 规范模型编辑、形变工作台、接口吸附、随机网格预览、共享面检查、源模型 FBX 导出 | 挂接点制作与预览、装配描述导出、混合模块预览 |
| Unity 导入 | 状态模型扫描、规范范围检查、模型库绑定、旋转镜像派生、共享面轮廓检查 | 装配描述导入、挂接点和接口校验、刚性资产目录 |
| Unity 生成 | Cell 状态选 Mesh、形变、对象池、脏 Cell 更新、原型撤销 | 语义布局、跨 Cell 占用、刚性装配、分段生成、连接件 |
| 交付 | 现有原型可操作 | 建筑保存、碰撞与导航更新、预算与发布检查 |

当前入口与依据：

- [Blender 工具说明](../Tools/Blender/README.md)。
- [形变与导入说明](../Assets/Scripts/Hexagonal/MarchingCube/README.md)。
- [建造原型说明](../Assets/Scripts/Hexagonal/Prototype/README.md)。
- 状态与方向约定：`CubeTransform.cs`；绑定：`ModelLibraryBinding.cs`；生成：`ModelBuilder.cs`。

## 2. 生产顺序与交接门槛

按以下顺序推进。每一步通过检查后再交接，避免到 Unity 中才发现固定尺寸部件无法与形变外壳贴合。

| 阶段 | 主责 | 输入 | 必须交付 | 通过条件 |
| --- | --- | --- | --- | --- |
| 规格定义 | 策划、技术美术、程序 | 建造玩法和参考 | 模块清单、尺寸表、合法形状范围、性能目标 | 可明确判断某种布局是否允许 |
| 白盒验证 | 技术美术、程序 | 尺寸和接口 | 灰模、占用范围、接口示例 | 固定尺寸与不规则网格能同时成立 |
| 正式建模 | 美术 | 已验证白盒 | 源文件、Mesh、材质、挂接点、碰撞代理 | 接口和枢轴合格，形变不破坏结构 |
| 源端检查 | 技术美术 | 源资产 | 形变、接缝、旋转镜像检查结果 | 在声明支持的范围内通过 |
| 导出与导入 | 技术美术、工具程序 | FBX、装配描述 | Unity 模型、Prefab、配置、导入报告 | 尺寸轴向一致、引用完整、重导入稳定 |
| 布局与生成 | 引擎/玩法程序 | 配置、网格、语义请求 | 外壳、刚性物件、连接件 | 占用无冲突、接缝合格、生成可复现 |
| 游戏集成 | 玩法程序 | 生成结果 | 碰撞、交互、导航、保存 | 玩家实际可用、可重建 |
| 验收与入库 | 美术、程序、测试 | 验证场景和报告 | 合格资产版本 | 功能、视觉、资源生命周期和预算通过 |

## 3. 首先冻结的项目规格

在批量建模前，为一个资产族填写下表。数值由白盒验证决定；本文不把示例尺寸作为项目既定值。

| 规格项 | 必填内容 |
| --- | --- |
| 世界尺寸 | 单位换算、标准层高、典型 Cell 尺寸 |
| 几何限制 | Cell 最小/最大边长、最小角度、最大宽高比；禁止翻转、自交和退化 |
| 建筑尺寸 | 墙厚、门窗净空、柱截面、楼梯踏步及通行要求 |
| 接口族 | 墙面接缝、门框、栏杆端头、柱脚等接口及版本 |
| 适配范围 | 哪些部分可拉伸、允许的长度范围、接缝容差、填缝范围 |
| 方向策略 | 支持的旋转、是否允许镜像、镜像替代资产 |
| 资源预算 | 目标设备、典型/最大规模、CPU/GPU 时间、内存、实例及材质预算 |

网格合法范围必须先确定。源模型无法保证在任意扭曲的四边形中保持质量；不合格 Cell 应在布局阶段被拒绝或修正。

## 4. 资产分类与制作要求

### 4.1 Deform：整体形变

用于墙体填充、岩壁、土坡等。使用规范空间建模，沿可能弯折方向布置足够分段。固定尺寸细节不烘焙进需要大幅变形的结构。

边界属于共享接口：统一轮廓与采样约定。内部造型可以变化，接口不得独立随意修改。曲面平滑和 UV 密度单独检查；现有轮廓检查不覆盖法线接缝、内部相交和材质问题。

### 4.2 Rigid：刚性装配

用于门扇、门框、灯、设备、家具。按最终世界尺寸制作，指定安装枢轴与本地朝向。运行时默认保持资产缩放，不从形变导数继承非均匀缩放或剪切。

必须声明包围范围、安装净空、碰撞代理及镜像策略。交互脚本、灯光和碰撞器在 Unity Prefab 配置；FBX 负责几何。

### 4.3 Repeat：分段拼装

用于栏杆、围栏、管线、饰条。提供标准段、转角、起点、终点和必要的连接件。规定段长、接口朝向、允许转角及收口规则。

生成器先扣除端头长度，再安排标准段；剩余长度使用合法的可调段、短段变体或填充件。没有合法解时拒绝放置。普通刚性段不得为了凑长度被任意拉伸。

### 4.4 Hybrid：混合装配

混合模块是一份装配配方，引用形变部件、刚性部件和连接件。各部分单独管理几何、材质、碰撞和更新，不预先合并为一个全体形变的 Mesh。

固定门洞的首选实现：先确定门框的世界空间矩形及净空，再用左右填充墙、上梁与外侧 Cell 接口连接。洞口边界必须服从门框尺寸。

**普通双线性形变会同时改变洞口，增加一个门框挂接点不能固定洞口。** 第一版应限定为竖直墙面、水平门槛及可容纳门框的跨度，增加专用门洞填充生成器。斜墙、扭曲洞口或复杂多层开洞在有对应生成方案后再开放。

## 5. Blender 源文件规范

### 5.1 集合与命名

建议源文件按以下集合组织，名称是新流程约定：

```text
SRC_Deform       形变源网格，沿用八位状态码后缀
SRC_Rigid        刚性源网格
SRC_Connectors   收口、连接与填充件
AUTH_Anchors     挂接点和接口辅助对象
AUTH_Collision   碰撞代理
PREVIEW         测试与展示副本，不参与生产导出
```

形变源网格示例：`wall_00001111`。刚性网格示例：`door_frame_A`。挂接点示例：`anchor_lamp_01`。刚性物件不得伪装成状态模型交给现有状态扫描器。

当前状态扫描会拒绝重复源状态；同一资产族暂时保持一个状态对应一个明确源模型。材质、风格或随机变体需在新目录/配方层表达，再单独实现选择规则。

### 5.2 坐标、单位与枢轴

- 形变模板沿用本地 `[-0.5, 0.5]³`，Blender Z 向上，Unity Y 向上。
- 形变网格使用本地几何坐标；源库场景中对象的展示位置、旋转、缩放不作为模板尺寸。
- 不能对排列好的旧源库盲目执行“应用所有变换”，否则可能把展示变换烘入模板。
- 刚性物件采用明确的米制单位映射，安装点为枢轴，最终 Unity Prefab 根节点缩放应为 `(1,1,1)`；用一米标尺资产验证转换。
- 新挂接点在 Unity 规范空间约定 `+Z` 为安装面朝外方向，`+Y` 为上方向。Blender 作者工具应显示对应轴，不依靠肉眼猜测 FBX 轴转换。
- 挂接点保存于模板本地空间。禁止混用源对象的展示位置或 Blender 预览副本的世界坐标。

角点编号沿用 `CubeTransform.GetCorner`。状态字符串从左到右对应 V1–V8，最左位对应 bit 0。不得按常见二进制字符串习惯反转。

### 5.3 接口与形变质量

1. 使用现有“吸附并登记所选接口”对齐边界；接口属性保存在源网格中。
2. 对新增内部顶点检查接口登记，防止挤出继承登记后被误吸回边界。
3. 检查标准、窄、宽、斜切和接近合法极限的 Cell。
4. 检查声明支持的四个旋转及镜像组合。
5. 检查 UV、法线、背面、细长三角形和局部穿插。需要时调整拓扑或缩小适配范围。

### 5.4 材质与碰撞

材质槽使用稳定的角色名称，例如 `WallBody`、`Trim`、`Metal`，在 Unity 显式映射材质。重导出不得无意改变槽位顺序。现有形变保留子网格，但装配系统仍需补齐材质绑定。

刚性部件优先使用简单碰撞代理；形变外壳需单独定义碰撞生成策略。不能把视觉 Mesh 更新等同于碰撞或导航已更新。三角面、材质数量和纹理预算以目标设备实测确定。

## 6. 挂接点、接口和装配数据契约

第一版建议：Blender 导出 FBX 和带版本号的同名 JSON；Unity 导入器把 JSON 转换为配置资产。运行时读取配置资产，不读取 Blender 源文件。

当前“仅导出源模型”只覆盖已有状态网格。刚性网格、挂接点和 JSON 导出属于新增工具工作，不能假设现有导出器已支持。FBX Empty 节点可用于调试显示，生产配置以经过验证的装配描述为准。

| 数据 | 必需字段 | 用途 |
| --- | --- | --- |
| 模块 | `schemaVersion`、稳定 `moduleId`、分类、资产引用、接口版本、允许变换 | 稳定识别与兼容检查 |
| 挂接点 | 稳定 `anchorId`、模板位置、朝外/向上轴、安装类型、偏移单位 | 放置刚性物件 |
| 接口 | `interfaceId`、版本、局部轮廓/尺寸、兼容标签、容差 | 判断能否连接 |
| 部件 | Prefab 引用、生成方式、支持的尺寸范围、镜像策略 | 执行装配 |
| 配方 | 语义条件、部件清单、挂接关系、占用与净空、失败策略 | 组合多个部件 |
| 派生实例 | 来源配方、稳定布局键、部件角色、种子/变体、依赖范围 | 更新、回收及保存重建 |

JSON 保存稳定 ID，不保存机器绝对路径。Unity 侧维护 ID 到 Mesh/Prefab/配置资产的映射，正常提交 `.meta` 以保留 GUID。重命名不改变 ID；复制成独立模块必须分配新 ID。FBX 子网格改名或拆分后必须重新检查引用。

制作阶段的接口几何与规则应只有一个权威来源；Unity 可配置玩法参数，但不能无提示地覆盖 Blender 导出的同名几何数据。

## 7. 导出、导入与失败处理

### 7.1 导出交付包

每个资产族交付源 `.blend`、FBX、装配 JSON、材质/贴图、规格表及检查结果。建议源文件、导出物与 Unity 配置分别放置：

```text
ArtSource/PCG/<Family>/       新资产族源文件；旧 PCG.blend 暂保留原位置
Assets/Art/PCG/<Family>/     FBX、贴图、材质、刚性 Prefab
Assets/PCG/Definitions/      导入后的模块和配方配置
Docs/PCG/Validation/         验收记录
```

这些目录为建议布局，本次文档没有迁移已有资产。

形变模板继续使用现有源模型导出，轴设置沿用工具的 `-Z Forward / Y Up`。新刚性/装配导出必须通过标尺、方向轴和挂接位置的 Unity 对照场景验证，不能只凭导出选项认为转换正确。

### 7.2 Unity 导入步骤

1. 扫描并展示变更清单，检查版本、ID 唯一性、引用、尺寸和轴向。
2. 对形变模型执行现有范围、状态覆盖及共享面轮廓检查。
3. 对刚性模块检查枢轴、尺寸、材质、碰撞、镜像支持及净空。
4. 对装配配方检查接口兼容、循环挂接、缺失部件及非法尺寸范围。
5. 全部通过后更新配置；重导入先重新取得 FBX 子资产引用，再重建缓存。
6. 在验收场景生成样例，输出可定位到模块、接口和原因的报告。

现有入口：`Tools > Marching Cube > Batch Mesh Importer`，默认绑定 `Assets/Art/BaseModel/PCG.fbx`；`Rebind PCG Library` 可重复绑定默认库。混合资产仍需开发新入口或扩展该窗口。

失败时保留上一份可用配置，禁止静默替换成空模块。源文件已被修改时，上一份配置不等于完整旧几何；恢复旧几何需从版本控制恢复整套源、导出物和配置。

## 8. Unity 引擎实现边界

保留现有 `ModelLibrary → ModelBuilder → MeshDeformation` 的外壳生成路径。新增装配层组合这些能力，逐步接入，避免一次改写状态表和全部资产。

| 建议模块 | 职责 | 不应承担 |
| --- | --- | --- |
| `ModuleDefinition` | 描述资产、挂接点、接口、合法范围 | 保存场景运行实例 |
| `AssemblyRecipe` | 定义模块组合及替代策略 | 直接修改源 Mesh |
| `LayoutPlanner` | 决定入口、门窗、楼梯、墙段、占用与净空 | 按三角形猜测玩法语义 |
| `AssemblyBuilder` | 按布局调用形变、刚性和分段生成 | 自行改变布局来掩盖失败 |
| `OpeningBuilder` | 固定门洞与外部 Cell 边界之间的填充 | 假定普通形变能保持洞口尺寸 |
| `AttachmentResolver` | 计算挂接姿态、镜像及接口适配 | 给刚性物件施加剪切 |
| `AssemblyInstanceRegistry` | 实例归属、依赖、替换和回收 | 拥有源导入资产 |
| 编辑器导入与校验工具 | 导出描述转换、资产绑定和报告 | 被运行时程序集依赖 |

上述模块尚未实现。起步时可放入现有程序集中的独立目录，边界稳定后再拆程序集。

## 9. 生成顺序与几何算法

### 9.1 先布局，再生成

1. 根据网格拓扑与启用状态识别候选表面、边界和转角。
2. 结合额外语义请求确定入口、门窗、楼梯等；八位占用状态本身不包含这些信息。
3. 按优先级预留通道、门洞和大型设施，检查跨 Cell 占用及净空。
4. 选择装配配方和合法变体，先验证所有必需部件能放下。
5. 生成墙体/地面外壳；门洞区域使用专用填充方案。
6. 求解挂接点，生成刚性物件和分段部件，最后补连接件及装饰。
7. 更新碰撞、交互和导航，记录实例归属及依赖。

布局优先级建议：必要通行结构 → 主体结构 → 功能物件 → 装饰。功能部件不能因随机装饰而失去安装空间。现有运行时原型之外，还需明确编辑态预览与运行时模式的生成归属。

### 9.2 挂接姿态

位置使用与 Mesh 相同的映射 `F`，并遵守相同顺序：模板 X 镜像 → 模板绕 Y 旋转 → Cell 内形变 → Cell 世界姿态。映射应抽取为公共能力，不能在 Blender、Mesh 和挂接点中各维护一套不一致的公式。

当前映射是 X/Z 双线性插值、Y 按层高缩放，并非任意八角点三线性变形。第一版挂接必须匹配这一真实行为。

朝向由表面两条切向映射求得，再叉乘并正交化。非均匀形变下不能直接把普通方向向量的变换结果当作法线。优先用解析导数；数值差分用于校验，边界需采用单侧差分，避免水平坐标截断导致零向量。

把正交姿态赋给刚性 Prefab，缩放保持配置值。壁灯的离墙距离等米制偏移，在姿态求解后沿单位法线施加，避免偏移随墙体宽度变化。

镜像要同时更新锚点位置、接口标签和方向；正交旋转本身不能表达反射。刚性物件声明 `禁止镜像`、`对称复用` 或 `左右替代资产`，默认不通过负缩放处理有交互或文字的物件。

### 9.3 占用与唯一归属

共享面的 `FaceKey` 和共享边的 `EdgeKey` 可用于本次网格实例中的去重。生成键应包含拓扑实体、部件角色及挂接点 ID，不能只包含空间坐标。

现有顶点 ID 不应未经验证就作为跨存档稳定 ID。持久化需定义可重建的布局坐标/持久 ID，并保存网格参数与生成器版本，或保存实际拓扑和顶点位置。

跨 Cell 门洞和楼梯由一个装配实例拥有，登记全部占用单元和依赖。共享面采用唯一所有者或集中生成表，避免相邻 Cell 各生成一次。

## 10. 编辑、撤销、资源与保存

- 编辑先形成布局事务，再更新几何。必需部件无合法解时回滚事务，界面说明具体原因。
- 修改一个点后，更新相关 Cell，再扩展到受影响的共享面、边、跨 Cell 装配及净空依赖，不能仅刷新最初的脏 Cell。
- 先构建并验证新结果，再替换旧结果；失败保留可用实例，不能留下半扇门或残余碰撞。
- 对象池回收时解除交互注册、关闭灯光/碰撞、清除实例归属和布局绑定。形变输出 Mesh 的所有权继续遵守现有组件约定。
- 源资产为只读输入；每实例形变输出由实例拥有，模板采样缓存由模型库拥有。刚性实例共享源 Mesh 和材质，避免无意克隆材质。
- 碰撞和导航可以分批重建，但完成前必须有明确的交互状态策略；测试玩家不能穿越未更新的墙或使用失效楼梯。
- 保存布局、语义选择、模块 ID、配方/生成器版本、种子和必要的人工覆盖；不只保存生成后的 Mesh。
- 随机变体使用稳定布局键派生局部种子；编辑其他区域不应导致整片建筑重新随机。
- 旧配方版本迁移必须有策略；缺失资产、失效占用和非法尺寸要报错并定位，禁止静默改变玩家建筑。

## 11. 首个资产族的完整示例

先制作“单层竖直墙段 + 固定门框/门扇 + 壁灯”，限制到可验证范围。

| 内容 | 美术交付 | 引擎处理 |
| --- | --- | --- |
| 普通墙 | 接口一致的规范墙模板 | 现有状态选择与形变 |
| 门洞墙 | 两侧填充墙、上梁和外侧接口；固定洞口规格 | 先预留矩形洞口，再生成到外边界的填充 |
| 门框/门扇 | 米制尺寸、安装枢轴、开门转轴、碰撞代理 | 刚性放置，Unity 配置开门交互 |
| 壁灯 | 安装枢轴、朝外轴、安装包围范围 | 求解表面姿态与固定离墙偏移 |
| 门套/填缝 | 明确遮盖与适配范围 | 仅在合法误差范围内收口 |

操作示例：用户指定入口 → 检查墙宽、层高、门扇扫掠净空和通行范围 → 预留占用 → 固定门框位置 → 生成周围墙体 → 放置门与灯 → 更新碰撞。墙太窄时拒绝入口，或采用用户允许的小规格变体；不自动压扁门框。

## 12. 验收矩阵与通过标准

| 类别 | 必测场景 | 通过标准 |
| --- | --- | --- |
| 坐标转换 | 一米标尺、方向轴、模板角点、挂接点 | Blender 与 Unity 对应；刚性尺寸和朝向正确 |
| 外壳接缝 | 不同状态、共享面、四向旋转和镜像 | 轮廓容差达标，观察无明显裂缝；另检法线/材质 |
| 合法形变 | 最窄、最宽、斜切、合法极限 | 无翻面、自交、明显失真或超范围刚性重叠 |
| 门洞 | 最小合法墙段、不足尺寸、门扇开启 | 门框保持规格，洞口匹配，非法布局明确失败 |
| 共享位置 | 两 Cell 同面/边、跨 Cell 模块 | 必需部件只生成一次，删除后无残留 |
| 依赖更新 | 改点、改层高、移除支撑、清空 | 所有相关装配、碰撞与交互同步 |
| 可复现 | 相同输入重建、改变遍历顺序、修改远处区域 | 布局与局部变体稳定 |
| 生命周期 | 反复构建、回收、重进 Play、重载资产 | 无持续资源增长，无过期绑定 |
| 保存 | 保存重载、旧版本、缺失模块 | 可重建；不兼容时给出具体诊断 |
| 性能 | 目标设备典型/最大规模、连续编辑 | 达到事先登记的耗时和内存预算 |

每次验收记录资产版本、合法范围、种子、布局、工具/引擎版本、失败位置及截图。数值容差需要按规范空间与世界空间分别定义，不能把模板单位的容差直接当作米。

当前可运行的源端检查：

```powershell
python Tools/Blender/tests/test_core.py
blender -b Assets/Art/BaseModel/PCG.blend --python Tools/Blender/tests/blender_smoke.py
```

上述命令需本机 Python/Blender 可用；Blender 检查成功标记为 `BLENDER_SMOKE_OK`。Unity 可在 Test Runner 运行现有 `TopologyTests`、`ModelStateTests`、`MeshDeformationTests` 与 `GridPrototypeTests`。这些现有检查不代表新装配能力已验证，新增能力需补充对应验证。

## 13. 实施里程碑

| 阶段 | 范围 | 完成门槛 |
| --- | --- | --- |
| M0：合同与白盒 | 坐标、ID、接口、合法范围、示例灰模 | Blender 和 Unity 一米标尺/轴向一致；固定门洞方案成立 |
| M1：刚性挂接 | 描述导出/导入、统一映射、壁灯挂接、回收 | 墙形变时灯保持尺寸；旋转镜像正确；重导入稳定 |
| M2：混合门洞 | 语义选择、占用、固定洞口填充、门交互 | 门框不变形、洞口贴合；空间不足明确失败 |
| M3：分段与依赖 | 栏杆、端头、共享归属、跨 Cell 更新 | 段长/收口合法；编辑和撤销无重复或残留 |
| M4：生产交付 | 保存迁移、碰撞导航、批量校验、性能报告 | 目标设备最大规模验收；资产制作可由另一名成员复现 |

按每阶段验收结果再估算工期。先完成一个资产族的全部链路，再批量扩充美术内容；节点编辑器、通用布尔和任意建筑语法留待实际生产需要明确后评估。

## 14. 提交与维护

提交源 `.blend`、约定的生产 FBX/JSON、Unity Prefab/配置/材质及 `.meta`、工具源码和验收记录。生产导出物随源文件一起更新，避免他人必须安装 Blender 才能打开项目。

不提交临时预览副本、工作台缓存、`Library`、`Temp` 和机器绝对路径。调试场景若作为正式验收样例，应显式纳入版本控制。

接口变化需提升接口版本，并列出受影响模块；仅改内部造型且接口不变，可保留接口版本。更新导入工具、映射公式或生成算法时，同步更新本文、样例和相关验证。
