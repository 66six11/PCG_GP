# 建筑 WFC 模块选择

入口仍为 UnifiedGridBuildingDemo.unity。玩家增删网格点决定占用，地形按底层数据Cell贴合；
WFC只在同一占用状态的候选模块之间选择，不扩张、删除或改写玩家的建筑。
面板新增“WFC 换一组建筑模块”，可撤销。相同模型库、占用状态和种子得到相同结果。

## 数据链路

1. UnifiedGridDocument产生脏Cell及建筑随机种子。
2. BuildingWfcCatalog从原始模型及旋转、镜像构造候选，保留原单状态查表会丢弃的变换。
   当前素材库得到424个变换候选；并不代表424种全新的建筑美术样式。
3. 每个候选按6个共享面提取真实几何边界，量化到1e-4模板单位，并合并无分叉的共线细分边。
   共享面采用同一组数据顶点建立方向，处理不规则网格中局部面朝向、旋转和翻转的差异。
4. 候选域先由Cell的8位占用状态和相邻空/实Cell约束过滤；WFC按加权最小Shannon熵观察、坍塌、传播。
   基础查表模块权重为4，其余变换权重为1。
5. 矛盾时沿删除记录回溯；每个建筑连通区域最多4096次观察。求解失败时只使用经共享面验证的基础模块，
   面板报告回退。如果基础库本身也无法满足接口则报错，不发布半坍塌结果。
6. ModelBuilder.Build(ModelInfo)验证占用状态后生成选中模块；模块变化时同步更新模型碰撞。

算法背景参考[WFC原始说明](https://github.com/mxgmn/WaveFunctionCollapse#algorithm)及其simple tiled model。
这里实现的是支持任意Cell邻接图的独立运行时求解器，没有新增外部包依赖。

## 局部性与复现

新增或删除点时，从脏Cell及邻接Cell收集受影响的当前连通区域。删除连接处会重新求解拆分后的各部分；
其他独立建筑的已选模块保留。组件内部排序和种子依据稳定的网格索引，不使用Unity对象实例ID。
撤销恢复占用或随机种子后，重新计算同一确定性坍塌结果。

回溯只记录候选删除的增量，不为每次观察复制整个区域的候选域。
目前为同步CPU求解，约束传播在区域内达到固定点；尚无跨帧调度或Jobs并行。
模型库改变后需要重新初始化demo以重建候选和接口缓存。

## 存档与验证

存档v3新增wfcSeed，文件为Application.persistentDataPath/unified-grid-building-v3.json。
读取依次回退到v2、v1；旧版本使用默认种子42，不覆盖旧文件。
历史记录包含种子，WFC选择结果和派生碰撞不直接保存。

Run Regression Tests菜单包含约束传播、带权观察、成功回溯、无解、预算上限、种子复现、
真实模型接口一致、局部编辑与撤销复现，以及统一网格/地形/模型变形回归。
Validate and Capture增加候选数、观察次数、传播删除数、回溯次数、回退数和共享面校验结果。

## 当前素材限制

现有模型按占用状态已经做过无缝兼容修正，多数同状态候选的面接口等价，因此默认示例可能没有候选被传播删除，
并不需要回溯。求解器的非平凡传播、冲突和回溯由专门的规则图测试验证。
现阶段WFC不自动创造新的屋顶、门窗、拱廊或结构支撑；需要继续补充带不同接口的候选模型及对应规则，
才能表现更丰富的Townscaper式建筑变化。当前仍保留原始自由点编辑及悬空结构，不进行重力稳定性检查。
